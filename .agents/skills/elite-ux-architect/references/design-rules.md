# デザインルール（数値で決める）

UI を作るときは、この表の値だけを使う。値の実体は [assets/tokens.css](../assets/tokens.css)、部品の実装は [assets/base.css](../assets/base.css)、実際の画面は [assets/exemplars/](../assets/exemplars/) にある。「なんとなく良さそうな値」を新しく作らない。

> 各ルールの根拠の強さ（規範・研究・経験則）は [evidence-ledger.md](evidence-ledger.md) にある。WCAG 由来の値は守る。経験則の値は出発点なので、理由があれば変えてよい（変えたら報告に書く）。

---

## 1. 色

| ルール | 値・やり方 |
|---|---|
| 背景は 4 段まで | `--bg`（ページ）→ `--surface`（カード）→ `--surface-2`（薄い面・表の見出し）→ `--surface-3`（hover・トラック） |
| 文字色は 2 段 + 無効 | `--text`（本文・見出し）、`--text-muted`（補足）。`--text-faint` は無効状態と装飾だけ |
| アクセントは面積 10% 以下 | 主ボタン、リンク、選択中の印、グラフの主系列だけ。見出しや背景の大面積に使わない |
| ブランド色は色相で変える | `--brand-h`（0〜360）と `--brand-c`（0.17 以下）だけ変える。L（明るさ）は固定なのでコントラストが崩れにくい |
| 状態は色 + 文言 | 成功・警告・エラーはバッジやアイコンに必ず文言を添える（色覚特性への配慮。WCAG 1.4.1） |
| コントラスト | 本文・補足とも 4.5:1 以上、入力欄の枠とアイコンは 3:1 以上。変更したら `python scripts/ux_audit.py tokens --file <tokens.css>` |
| ダークモード | 純黒 `#000` と純白を使わない。影ではなく「面を明るくする」ことで重なりを表す |
| 色を混ぜるとき | 色相が離れた 2 色を `color-mix(in oklch, …)` で混ぜると途中の色相（赤＋青灰 → 紫）になる。`in srgb` で混ぜる。透明との混合は oklch で良い |
| グラフの系列 | `--chart-1`〜`--chart-5` の順に使う。6 系列以上はグラフの種類を見直す |

## 2. 文字

| 用途 | トークン | 実寸 | 太さ | 行間 |
|---|---|---|---|---|
| ヒーロー見出し | `--text-display` | 36〜60px（可変） | 700 | 1.25 |
| ページ見出し | `--text-4xl` / `--text-3xl` | 36 / 30px | 700 | 1.25 |
| セクション小見出し | `--text-2xl` / `--text-xl` | 24 / 20px | 600〜700 | 1.25〜1.45 |
| リード文 | `--text-lg` | 18px | 400 | 1.7 |
| 本文・入力欄 | `--text-base` | 16px | 400 | 1.7（長文 1.85） |
| UI ラベル・ボタン・表 | `--text-sm` | 14px | 500〜600 | 1.45 |
| 注記・バッジ | `--text-xs` | 12px | 500 | 1.45 |

- サイズはこの 10 段だけ。1 画面で使うのは 4〜5 段まで。15px、17px、22px のような中間値を作らない
- 太さは 400 / 500 / 600 / 700 の 4 つ。階層は「サイズ → 太さ → 色」の順で付ける
- 入力欄の文字は 16px 以上（iOS Safari が 16px 未満の入力欄でズームするため）
- 単位は rem。px で固定すると利用者のフォントサイズ設定が効かない
- 本文の書体は OS の書体（`--font-sans`）で良い。**個性は見出しの書体（`--font-display`）とブランド色で出す。** 既定のまま（欧文 Inter / Roboto、システムフォントだけ）だと既視感が出やすい（evidence-ledger.md G 章）。日本語の見出し書体の例：Zen Kaku Gothic New、M PLUS 1、BIZ UDPGothic、Noto Serif JP。Web フォントは見出しにだけ読み込む
- 高齢の方や公共・業務の利用者が多い画面は、本文に UD 書体（`"BIZ UDPGothic"` を `--font-sans` の先頭に。Windows 10 以降に標準搭載、Google Fonts でも配布）を検討する。濁点と半濁点、`0` と `O`、`1` と `l` が見分けやすい

### 日本語の文字組み

| ルール | CSS |
|---|---|
| 本文の行長は 35〜45 字（経験則。研究では 20 字前後で読む速さが頭打ちになるので 20 字未満は避ける） | `max-width: var(--measure)`（40rem） |
| 本文の行間は 1.7 以上 | `line-height: var(--leading-normal)` |
| 見出しは文節で折り返す | `word-break: auto-phrase; text-wrap: balance;` |
| 約物を詰めるのは見出しだけ | `font-feature-settings: "palt"`（本文には使わない） |
| 欧文の字間詰めは日本語に使わない | `letter-spacing: -0.015em` は欧文見出しだけ。`:lang(ja)` では 0〜0.02em |
| 数字は等幅・右揃え（表・金額・KPI） | `font-variant-numeric: tabular-nums` |
| 長い英数字ではみ出さない | 全体に `overflow-wrap: break-word`。`anywhere` は表やフレックスを押しつぶすので全体には使わない |
| 禁則 | `line-break: strict` |

## 3. 余白

4px 刻みのトークン（`--space-1` = 4px 〜 `--space-32` = 128px）だけを使う。

| 関係 | 間隔 |
|---|---|
| 部品の内側（アイコンと文字など） | 4〜8px（`--space-1`〜`--space-2`） |
| 関係の深い要素どうし（ラベルと入力欄） | 8px（`--space-2`） |
| 同じグループの項目どうし（フォームの行） | 16〜24px（`--space-4`〜`--space-6`） |
| グループどうし（カードどうし） | 16〜24px（`--space-4`〜`--space-6`） |
| セクション見出しと中身 | 32〜48px（`--space-8`〜`--space-12`） |
| セクションどうし | 64〜96px（`clamp(--space-16, 9vw, --space-24)`） |
| カードの内側 | 24px（スマホ 16〜20px） |

- **近いものは近く、違うものは遠く。** 全部 16px の「均一な余白」はグループが見えなくなる
- 見出しは「下の内容」に属する：見出しの上の余白 ≥ 見出しの下の余白 × 2
- 区切り線を足す前に、余白だけでグループを分けられないか試す
- **粒度の違うもの（見出しと本文）を 1 つの `gap` で並べない。** 親の `gap` は全部の子に同じ値がかかるので、見出しが前のブロックと自分の本文のちょうど中間に浮く。見出し自身に上の余白を持たせる（`.topic-title { margin-top: var(--space-12) }`、親の `gap` は小さく）か、項目ごとにカードや罫線で区切る
- 意味の違いを余白で表すときは、トークンを 1 段飛ばして使う（16px と 20px の差は見分けられない。16px と 24px、24px と 48px のように差を付ける）
- 一覧・比較は要素間を詰めてグループ間を空ける。情報量を減らさずに読みやすくするには、余白を削るのではなくグループ化して階層を作る

## 4. 角丸

| 要素 | トークン |
|---|---|
| バッジ・小ボタン | `--radius-sm`（6px）または `--radius-full` |
| ボタン・入力欄 | `--radius-md`（8px） |
| カード | `--radius-lg`（12px） |
| ダイアログ・大きなパネル | `--radius-xl`（16px） |
| ヒーローの画像・CTA の帯 | `--radius-2xl`（24px） |

- 入れ子は「外側の角丸 = 内側の角丸 + 間の余白」。同じ値にすると内側が太って見える
- 1 画面で使う角丸は 3 種類まで

## 5. 影と重なり

| 段 | 用途 |
|---|---|
| `--shadow-xs` | secondary ボタン、入力欄の浮き |
| `--shadow-sm` | セグメントの選択中、スイッチのつまみ |
| `--shadow-md` | hover で浮くカード、`.card--raised` |
| `--shadow-lg` | ドロップダウン、ポップオーバー、目立たせる料金カード |
| `--shadow-xl` | ダイアログ、ヒーローの製品画面 |

- 1 要素につき影は 1 段。枠線と強い影を同時に使わない（カードは「枠線だけ」か「影だけ」）
- 面の重なりは z-index トークン（`--z-sticky` 〜 `--z-toast`）で管理する

## 6. レイアウト

| ルール | 値 |
|---|---|
| コンテンツの最大幅 | `--container`（72rem = 1152px）、フォーム中心の画面は `--container-narrow`（48rem） |
| 左右の余白 | `clamp(16px, 4vw, 32px)`（`.container` に入っている） |
| ブレークポイント | 640 / 768 / 1024 / 1280px（`40rem` / `48rem` / `64rem` / `80rem`）。スマホから書いて `min-width` で足す |
| 管理画面のサイドバー | 240px（`--sidebar-w`）。1024px 未満では隠してメニューボタンに |
| 揃え | 本文・リスト・フォームは左揃え。中央揃えは短い見出し・空状態・CTA だけ |
| 1 行に並べるカード | 2〜4 枚。同じ大きさのカードを 6 枚以上並べるより、重要なものを大きくする |

## 7. 部品の大きさ

| 部品 | 高さ |
|---|---|
| 小ボタン・セグメント | 32px（`--control-sm`） |
| ボタン・入力欄 | 40px（`--control-md`） |
| 大ボタン（ヒーロー・主要 CTA） | 48px（`--control-lg`） |
| タッチ端末 | 44px 以上（`base.css` が `pointer: coarse` で自動で広げる）。最低でも 24px（WCAG 2.5.8） |
| アイコン | 16 / 20 / 24px、線幅 1.75、`currentColor` |

## 8. 動き

| 用途 | 時間 | イージング |
|---|---|---|
| hover・押下 | 120ms（`--dur-1`） | `--ease-out` |
| 開閉・切り替え | 200ms（`--dur-2`） | `--ease-out` |
| 画面内の大きな移動 | 320ms（`--dur-3`） | `--ease-in-out` |

- 動かすのは `transform` と `opacity` だけ（`width` / `height` / `top` / `left` はレイアウト計算が走ってカクつく）
- `prefers-reduced-motion: reduce` では動きを止める（`base.css` に入っている）
- `transition: all` は使わない。動かすプロパティを列挙する

## 9. 状態

すべての画面・部品について、次の状態を作ったかを確認する。

| 状態 | やり方 |
|---|---|
| hover / focus / active / disabled | `base.css` の各部品に定義済み。フォーカスは `:focus-visible` のリング（消さない） |
| 読み込み中 | 実際のレイアウトと同じ形のスケルトン（目的は表示後のレイアウトのずれ防止と内容の予告。体感速度が上がるかは研究で割れている）。ボタンは幅を変えず「保存中…」 |
| 空（0 件） | アイコン + 何がないか + 次の行動のボタン（`.empty`） |
| エラー | 欄の直下に、何が問題で、どう直すか（`.error-text`）。画面全体の失敗は `.alert--danger` |
| 成功 | 取り消せる操作はトースト + 「元に戻す」。確認ダイアログで止めない |
| 長いデータ | 長い名前・0 件・1000 件・桁の多い金額で崩れないか |

## 10. 文言

- ボタンは動詞で結果を言う：「OK」ではなく「削除する」「保存する」
- 見出しは利用者にとっての結果を書く：「革新的なソリューション」ではなく「会議のメモが、そのままタスクになる」
- 数字は具体的に：「大幅に削減」ではなく「転記作業を 82% 削減」
- エラーは責めずに直し方を書く：「無効な入力です」ではなく「@ の後ろにドメインを入れてください」
- エラーには **何が起きたか・なぜか・どう直すか** を入れ、入力した内容は消さない（「通信が切れたため送信できませんでした。入力内容は残っています。もう一度『送信する』を押してください」）
- 入力欄のエラーは、その欄のすぐ下に出す。打っている途中では出さず、欄を離れたときか送信時に出し、直したらすぐ消す

## 11. アイコン

- **アイコンを使うのは「操作・ナビゲーション・状態」を見分けるときだけ。** 見出しや説明カードの飾りに付けない（付けたくなったら、実際の画面の一部や数値を見せる）
- アイコンには常に見えるテキストラベルを付ける。ラベルなしで通じるのは検索（虫眼鏡）・閉じる・メニューなど少数（NN/g、evidence-ledger.md I 章）
- アイコンだけのボタンは、ラベルなしで通じるものに限り、`aria-label` を付ける
- インライン SVG（`<symbol>` + `<use>`）か、プロジェクトのアイコンライブラリ（lucide など）を使う
- 絵文字をアイコン代わりに使わない（OS で見た目が変わり、線の太さもそろわない）
