# VS Code プロキシ設定の保存・復元調査

**日時**: 2026-10-07

**深刻度**: Major（プロキシ接続が必要な環境で再接続に影響）

SSH 接続した VS Code の settings.json でプロキシ行のコメントアウトを解除しても、ウィンドウの再起動で元へ戻るという報告を調査した。

## 確認した原因と対応

| 問題 | 原因 | 対応 |
|---|---|---|
| 専用窓の設定が Roaming の内容へ戻る | `TryShareInstalledSettingsFile` が既存ファイルを削除し、Roaming へハードリンクを作り直す | 既存ファイルを保持し、無い初回だけリンク作成 |
| ハブ管理を有効にすると窓で保存した有効・無効が戻る | `MergeDedicatedSlotSettings` が起動のたびにハブのプロキシ設定を適用する | 初期値は新規ファイルだけ。既存ファイルへの変更は「全パネルへ適用」に限定 |
| ファイルと起動プロセスのプロキシ状態が異なる | 起動環境変数が保存済み窓設定よりハブ設定を優先する | ハブ管理有効の専用窓は、その窓の保存済み設定から環境変数を決定 |

再現テストは、一時ディレクトリ内で Roaming 相当のコメントアウトされた設定と、パネル側で有効にした設定を用意し、リンク作成・専用設定同期を2回実行する。初回リンク後に別ファイルを置換保存するケースも含める。実ユーザーのプロキシ、SSH 接続先、実行中の VS Code は変更しない。

## 検証結果

- 修正前: 再リンクによる巻き戻し2件と、ハブ管理による有効/無効上書き2件が失敗。
- 修正後: 既存55件と追加7件、全62件合格。設定保持のテストは全22件合格。
- 本体・テストのビルド: 警告0、エラー0。出力先は `.build-tmp/proxy-settings-20261007` に隔離。
- リンクが続いている場合の通常設定共有、初回設定の引き継ぎ、コメント保存、標準設定への書き込み禁止も既存テストで確認。
- 常駐監視・追加プロセス・設定の常駐キャッシュは追加しない。専用 user-data を自動で有効にしないため、今回の修正によるスロット数分の VS Code プロセスや Chromium キャッシュ増加は生じない。実端末でのメモリ使用量測定は未実施。

## 報告されたウィンドウとの照合

作業中にユーザーから「プロキシ設定はこの環境ではなく別PC」と補足された。開発PCで確認した共有モード設定は、報告の原因判断には使わない。

別PCで開いている設定がユーザー・リモート・ワークスペースのどれかとファイルのパスは未確認。今回の修正はハブの専用プロファイル起動処理にある再現済みの巻き戻しを防ぐもので、別PCでの SSH 再接続の実動作は未検証。SSH の場合もローカルのユーザー設定は使用され、リモート設定は接続先ごとに別に扱われる（[VS Code Remote SSH 公式ドキュメント](https://code.visualstudio.com/docs/remote/ssh#_remote-settings)）。対象ファイルが判明したら、保存先と起動時の設定スコープを照合できる。

## 再発防止

- 起動時に既存の settings.json を削除・再リンクする処理を再導入しない。
- ハブ設定の明示適用と、VS Code の保存内容を維持する起動処理を区別する。
- JSONC のコメントアウト解除・再コメントアウト、ファイル置換保存、連続再起動を回帰テストで確認する。
