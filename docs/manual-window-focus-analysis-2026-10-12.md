# ウィンドウの直接操作とフォーカス同期

日時: 2026-10-12  
深刻度: Major（作業中の手動最大化が取り消される）  
状態: 修正済み。実際の IDE を操作した目視確認は未実施。

## 現象と原因

パネルではなく管理ウィンドウの最大化ボタン・タイトルバーダブルクリックで最大化すると、`WindowSlot.IsFocused` が実体と一致しなかった。旧フォーカスの Z 順補正が新しい最大化窓を背後へ戻し、起動後の遅延配置補正は手動最大化された窓を4面サイズへ復元していた。フォーカス窓の直接復元も再最大化され得た。

- 2026-04-28 頃にフォーカス再適用処理が導入された。2026-04-29 の `67dd4fb` は再適用を遅延させ、パネル入力中の抑制を追加した。記録上はパネルの応答性と配置の安定性が目的。
- 2026-06-07 の `aa52105` は直接最小化を尊重し、再最大化せずフォーカスだけ解除するよう修正した。

## 修正内容

1. `WindowFocusSynchronizer` が HWND ごとの最大化への変化を検出し、管理ウィンドウの直接最大化をフォーカスへ取り込む。同時に最大化した候補は実際に手前にある窓を優先する。
2. 同じディスプレイの旧フォーカスだけを解除し、最大化アニメーションの猶予後、非アクティブ・アニメーションなしで元の象限へ戻す。別ディスプレイのフォーカスと最小化済み窓は維持する。
3. 直接復元したフォーカス窓は自分の象限へ戻し、直接最小化はフォーカスだけ解除する。
4. 周期更新、起動後の配置リトライ、フォーカス再適用、Z 順補正、パネル切替の遅延整列より先に直接操作を取り込む。再接続直後の最大化も保護する。
5. 手動操作で古い遅延処理をキャンセルし、未完了の旧フォーカス復元は次の処理へ引き継ぐ。アプリ主導の非表示や最大化要求中は同期を保留する。

同期速度は既存の状態更新設定に従う（既定1000ms、設定範囲250～5000ms）。古いフォーカスが非同期復元待ちで最大化のままでも、同じ最大化状態を新操作として再採用しない。VS Code の設定・ストレージは変更しない。

## 実機の確認手順

1. 4面表示でAを直接最大化し、更新間隔と起動後の配置リトライを経ても最大化が維持され、パネルのフォーカス枠がAになること。
2. Bを直接最大化し、Aだけが元の象限へ戻り、Bが維持されること。A→B→Cを素早く操作しても最後の窓が維持されること。
3. フォーカス窓を直接復元して4面の象限へ戻ること。直接最小化では勝手に復元されないこと。
4. Cを最小化してからBを最大化してもCが最小化のまま残り、別ディスプレイのフォーカスも維持されること。
5. パネルからの切替、表示/非表示、ディスプレイ移動、カード入替の既存動作を確認する。
